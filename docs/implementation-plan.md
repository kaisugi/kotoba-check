# 実装計画

更新日: 2026-09-18

## 1. 基盤と技術検証（完了）

- Vite + TypeScriptの静的サイトを使う。
- 現行配布版 `lindera-wasm@6.0.0` を固定し、lockfileをコミットする。
- IPADIC 6.0.0をサイト自身から配信する。
- Worker内でWASMと辞書を一度だけ初期化し、Tokenizerを再利用する。
- LinderaのUTF-8バイト位置をUTF-16コード単位へ変換して原文と照合する。
- 開発サーバー、本番ビルド、実ブラウザで動作を確認する。

## 2. 検出処理（完了）

- `textlint-rule-preset-ai-words-ja@1.2.1` の `no-ai-words` の内蔵辞書を移植する。
- 形態素条件は `surface`、`lemma`、`pos`、`posDetail` の共通表現に変換する。
- 活用形と複数トークン表現を連続形態素の照合で検出する。
- 同じ範囲に意味の異なるルールが重なる場合は別々の指摘として保持する。
- 上流で既定無効の `no-short-topic-comma` も独立関数として移植するが、初期UIでは有効にしない。

## 3. UI（完了）

- 初期表示で大きなtextareaが見える構成にする。
- 文字数、指摘数、点検、クリア、コピーを配置する。
- 原文はDOMのテキストノードとして描画し、HTMLとして解釈しない。
- ハイライトまたは指摘カードを選ぶとtextareaの該当範囲を選択する。
- 辞書読み込み中、解析中、失敗、指摘なしを別々に表示する。
- 300 msの自動解析、IME変換中の抑止、request IDによる古い結果の破棄を行う。
- 760 px以下は縦一列にし、主要操作は44 px以上、入力文字は16 px以上にする。

## 4. テストと配布確認（完了）

- 上流の検出例・非検出例を実IPADICで確認する。
- 活用形、複数トークン、重複、絵文字、改行、辞書404を自動テストする。
- ChromiumでWorker解析、選択連携、HTML非解釈、375 px幅の横あふれを確認する。
- `dist` の全ファイルがCloudflare Pagesの25 MiB上限未満か確認する。

## 5. 文脈に合わせた表現ルール設定（完了）

- 各表現ルールをGUIのチェックボックスで個別にオン・オフできるようにする。
- 表現名の検索と一括オン・オフを用意する。
- 解析済みの指摘を設定に応じて再表示し、切り替え時に不要な形態素解析を繰り返さない。
- オン・オフ設定のみlocalStorageに保存する。本文は保存しない。
- 実ブラウザで「検査」「部品」の切り替え、再読み込み後の設定、本文の非保存を確認する。

## 次の候補

- 47.5 MBの初回転送量を減らすための軽量辞書または必要語彙辞書を比較検証する。
- 長文入力時のWorkerキャンセルまたは処理の協調的中断を検討する。
- 表現辞書の更新手順をスクリプト化し、上流差分を定期的に確認する。
- 必要性を確認してから、辞書編集UIとユーザー辞書を設計する。
